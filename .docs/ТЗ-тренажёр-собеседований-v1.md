# ТЗ: Тренажёр собеседований — бизнес-логика и UI/UX (v1)

*Статус: черновик для согласования. Фокус: воронка, экраны, что пользователь видит и нажимает. Технические детали (схемы БД, эндпоинты, промпты) — следующий этап. Июнь 2026.*

---

## 0. Что это и что НЕ входит в этот документ

Этот документ описывает **бизнес-логику и интерфейс**: воронку, экраны веба и Telegram, поведение, переходы. Здесь сознательно **нет** кода, схем БД, точных API-эндпоинтов и промптов — это отдельное техническое ТЗ на следующем шаге.

Согласованные решения (из обсуждения):
- Веб: **боковое меню + дашборд**, на мобильном — нижнее меню.
- Сессия на вебе: **Zoom-режим с камерой** (своя камера локально).
- Интервьюер: **аватар (выбор пола/стиля) + анимация речи** (пульс/эквалайзер), без видео-липсинка.
- База вопросов: **своя, генерируем LLM + вычитка** (не парсим конкурентов).

Подтверждённые решения (раунд 2):
- **Язык:** только русский на старте, но **vue-i18n используется на 100%** (весь UI через ключи `t('...')`), чтобы английский добавлялся одним файлом локали без переписывания. На английский сейчас время не тратим.
- **Голос (переносим из Mentala, 2 режима):**
  1. **Диктовка голосом в textarea** — `app/composables/speech/*` (движки `webspeech` бесплатный / `whisper` задел). Голос превращается в текст и вставляется в поле.
  2. **Real-time голосовой разговор** — `useRealtimeVoiceSession` + `server/api/realtime/*` через **OpenAI Realtime API** (это и есть «real-time voice», НЕ LiveKit — моя прежняя формулировка была неточной).
- **Интервьюер:** статичное фото (выбор пола/стиля) + анимация при воспроизведении голоса. Своя камера — через `getUserMedia` (локально, для погружения). AI-видео/HeyGen-аватары не делаем (дорого).
- **Распознавание речи:** на старте **стандартное браузерное (Web Speech API, бесплатно)**. Whisper или GigaAM/GigaChat — позже, по критерию «дешевле/качественнее» (помечено, решим перед масштабированием).
- **Оплата:** YooKassa (сайт) + Telegram Stars (бот).
- **Название:** рабочее **JobAI** (временное, поменяем позже). Домен пока не покупаем.
- **TTS (озвучка интервьюера):** переиспользуем подход Mentala (`server/api/tts`, `useTTS`); конкретный движок русского голоса — уточнить.

## 1. Продукт в одном абзаце

Этичный тренажёр собеседований для **всех профессий** (упор на не-IT масс-маркет). Пользователь вставляет вакансию (ссылка hh.ru или текст) и/или резюме, выбирает формат — и проходит **репетицию интервью голосом**: на сайте в виде имитации видеозвонка, в Telegram — через голосовые. После сессии получает **разбор**: оценку по критериям, ошибки, сильный вариант ответа по STAR и план «что исправить до интервью». Telegram — входная дверь и быстрые тренировки, сайт — глубина, отчёты, история, Zoom-режим и оплата.

## 2. Стек и что берём из Mentala

Берём «как есть» (обкатано, не изобретаем):
- **Фронт:** Nuxt 4 + Vue 3.5, Pinia, Tailwind 4 + shadcn-vue/reka-ui, vee-validate + zod, vue-i18n, vue-sonner (тосты), VueUse, `floating-vue` для `v-tooltip`.
- **Бэк:** Nitro (внутри Nuxt), Clean Architecture (api → application → domain → infrastructure), Drizzle ORM + Postgres (новая БД), BullMQ + Redis (очереди: генерация отчётов, база вопросов), pino, Sentry.
- **AI/RTC:** `openai` SDK (уже есть), OpenAI Realtime API, realtime-event adapter по образцу Mentala для превращения голосовых событий в обычную ленту сообщений.
- **Графики отчётов:** apexcharts/chart.js (уже есть).
- **Валидация DTO:** `shared/dto/*` на zod — как в Mentala (хендлер и фронт валидируют одной схемой).

НЕ берём на старте: Capacitor и всё нативное (iOS/Android), Firebase push, howler/нативное аудио, capacitor-* плагины. PWA по желанию позже.

Под уточнение: какие именно вспомогательные библиотеки тащить (gsap для анимаций, swiper, photoswipe) — решим точечно при вёрстке.

## 4. Воронка (главная логика роста)

1. **Привлечение.** Telegram (карьерные чаты, таргет «ищу работу», не-IT сообщества) + SEO-страницы базы вопросов на сайте.
2. **Активация.** Первая бесплатная быстрая сессия — пользователь сразу получает ценность (разбор + сильный ответ).
3. **Монетизация.** После бесплатной сессии — пейволл: «разовая подготовка» / «перед важным интервью» / «месяц поиска».
4. **Удержание.** Сессии под каждую новую вакансию (за поиск работы человек ходит на 5–15 собесов), библиотека своих заготовок, трекинг прогресса, напоминания.
5. **Мост Telegram → Web.** Из бота — на сайт за полным разбором (там выше ценность и проще продать подписку).

## 5. Категории/сферы: как пользователь выбирает направление

Принцип: **вакансия — главный персонализатор, список — только навигация.** Глубокое дерево не строим.

- **Шаг выбора направления (для тех, кто без вакансии):** топ-уровень из 12–14 сфер плиткой:
  IT/разработка · Продажи · Маркетинг/реклама · Менеджмент/руководство · Аналитика/данные · Дизайн · Финансы/бухгалтерия · HR/рекрутинг · Поддержка/клиентский сервис · Логистика/закупки · Инженерия/производство · Образование · Медицина · Юриспруденция · Ретейл/общепит · **+ «Другое (впишу сам)»**.
- **Внутри сферы — частые роли, но не глубже одного уровня.** Пример IT: Frontend · Backend · QA · Mobile · DevOps · Data · PM/Product · Analyst. И стоп.
- **Глубину (стек, грейд, специализация) НЕ зашиваем в дерево** — берём из текста вакансии и одного свободного поля «уточни специализацию» + селектор уровня (junior/middle/senior).
- **Кастомный ввод всегда доступен** — если сферы/роли нет, пользователь пишет своими словами, движок всё равно работает (опирается на вакансию).

Итог: если пользователь вставил вакансию — выбор сферы можно вообще пропустить (всё вытащим из вакансии). Список нужен для входа «без вакансии» и для SEO-навигации по базе.

## 6. Веб-версия — детальный UI/UX

### 6.1. Навигация (макет)
- **Десктоп:** фиксированное **левое меню** (иконка + подпись): Дашборд · Новое интервью · История · База вопросов · Тарифы · Профиль. Сверху справа — баланс сессий/тариф, аватар.
- **Мобильный (медиа-запросы):** левое меню сворачивается в **нижнюю таб-панель** (4–5 иконок: Главная, Новое, История, База, Профиль). Контент на всю ширину.
- Везде адаптив: сетки на `auto-fit/minmax`, отступы и типографика — масштабируются.

### 6.2. Главный экран (Дашборд) — что видит после входа
- **Крупный приоритетный блок «Начать интервью»** (главный CTA) — кнопка + краткое «Вставь вакансию или выбери профессию».
- **Карточка прогресса:** общий балл за последние сессии, мини-график «уверенность растёт», слабая зона недели.
- **«Продолжить подготовку»:** последняя вакансия/сессия с кнопкой «ещё раз».
- **Быстрые сценарии (плитки):** HR-скрининг · Профессиональное · Поведенческое · Зарплатные переговоры · Английский.
- **Блок «3 вещи исправить до интервью»** — из последнего отчёта (тянет назад в продукт).
- У бесплатного пользователя — ненавязчивый блок тарифа (видим, не скрыт; иконка тарифа).

### 6.3. Создание интервью (мастер настройки, 1 экран с шагами)
1. **Источник:** вкладки «Вставить вакансию (ссылка hh.ru / текст)» · «Выбрать профессию» · «Загрузить резюме (опц., PDF/текст)».
2. **Роль и контекст:** профессия/роль из списка или вручную, уровень `junior/middle/senior` с человекочитаемой подписью, компания, резюме.
3. **Свои вопросы:** опциональный блок «Что хочешь потренировать?». Пользователь может вставить список вопросов, написать свободным текстом или надиктовать голосом. AI нормализует ввод: разбивает на отдельные вопросы, убирает дубли, помечает тему и сложность.
4. **Источник вопросов:** сегментированный выбор:
   - «JobAI» — только наши вопросы под вакансию/роль;
   - «Мои + JobAI» — пользовательские вопросы вперемешку с нашими (рекомендуемый режим);
   - «Только мои» — интервьюер задаёт только то, что пользователь попросил потренировать.
5. **Формат:** вместо жёсткого выбора «3 / 6 / 10 вопросов» используем **цель сессии**:
   - «Быстрая» — 5-7 минут, примерно 3 ключевых вопроса;
   - «Стандартная» — 12-15 минут, примерно 5-6 вопросов;
   - «Глубокая» — 20-25 минут, примерно 8-10 вопросов.
   Внутри создаётся `interview_plan`: список обязательных и резервных вопросов. Количество не обещаем как жёсткое число, но отчёт всё равно строится по каждому фактически заданному главному вопросу.
6. **Тон интервьюера:** мягкий / нейтральный / строгий. **Аватар интервьюера:** выбор пол/стиль.
7. Кнопка **«Начать»** → экран сессии.

Важно: **режим ответа не выбирается заранее**. Текст, диктовка и realtime voice доступны уже в комнате интервью как способы ввода одного и того же ответа. Если realtime voice недоступен по тарифу или закончились минуты, показываем lock/paywall именно при попытке запуска realtime, не перегружая мастер создания лишней настройкой.

Подсказки также управляются **во время сессии**, а не как обязательная настройка в мастере. Пользователь открывает/закрывает панель подсказок и позже сможет выбрать поведение: без подсказок, по запросу или realtime-подсказки. В любом режиме подсказки не подставляются в ответ автоматически.

Если вставлена вакансия — поля «сфера/роль» автозаполняются, а JobAI заранее предлагает план вопросов. Пользователь может убрать лишние темы или добавить свои.

### 6.4. Экран сессии — Zoom-режим (ключевой экран)
Экран должен быть единым для текстового режима, диктовки и realtime voice. Не делаем отдельную механику «вопрос-ответ» для текста и отдельный голосовой экран: всё отображается в одной ленте интервью.

Рекомендуемый лейаут:
- **Верх/центр — сцена интервью:** карточка интервьюера с аватаром и анимацией речи, локальная камера пользователя, статус микрофона/голоса.
- **Центр — единый чат интервью:** сообщения интервьюера, вопросы, уточнения, ответы пользователя, live-транскрипт realtime voice. Текстовый ответ и realtime voice должны попадать в одну и ту же структуру сообщений.
- **Справа на десктопе — боковая панель:** текущий план интервью, активный вопрос, таймер сессии, подсказки, кнопка «Следующий вопрос». На мобильном эта панель превращается в нижний sheet/выдвижную панель.
- **Нижняя панель управления:** микрофон/realtime voice, диктовка, текстовый ввод, камера, повторить вопрос, подсказка, следующий вопрос, завершить.

Лента чата:
- Интервьюер задаёт главный вопрос как отдельное сообщение, привязанное к `interview_plan_item`.
- Пользователь отвечает текстом, диктовкой или realtime voice; live-транскрипт отображается в user bubble по мере поступления.
- Уточняющий вопрос отображается как вложенный/связанный с главным вопросом, но в отчёте остаётся частью анализа этого главного вопроса.
- Все режимы используют один `InterviewConversationStore`: обычный текст добавляется сразу, realtime voice — через адаптер событий OpenAI Realtime по образцу Mentala (`RealtimeVoiceChatAdapter`).

Как решаем проблему «сколько вопросов в realtime voice»:
- На старте создаём не жёсткое число вопросов, а **план интервью**: обязательные вопросы, резервные вопросы, пользовательские вопросы и ожидаемое время.
- В realtime voice интервьюер держит один активный главный вопрос. Пока вопрос активен, весь transcript пользователя мапится на этот вопрос.
- Переход к следующему вопросу происходит одним из трёх способов: пользователь нажал «Следующий вопрос», сказал «следующий вопрос», либо AI уверен, что ответ завершён и предлагает перейти.
- Если пользователь уводит разговор в сторону, это не ломает отчёт: transcript всё равно сохраняется в текущий вопрос, а подсказка может мягко вернуть к теме.
- В отчёте анализируем фактически заданные главные вопросы. Если часть плана не успели пройти из-за времени, она помечается как «не задано».

Завершение сессии:
- **Быстрая:** план 5-7 минут, предупреждение на 6-й минуте, hard-stop realtime voice на 10-й минуте.
- **Стандартная:** план 12-15 минут, предупреждение на 13-й минуте, hard-stop realtime voice на 20-й минуте.
- **Глубокая:** план 20-25 минут, предупреждение на 22-й минуте, hard-stop realtime voice на 32-й минуте.
- На soft-limit интерфейс мягко предлагает закончить текущую мысль или перейти к следующему вопросу. Не обрываем пользователя мгновенно.
- На hard-limit realtime voice останавливается автоматически, но пользователь может дописать ответ текстом и сформировать отчёт.
- Для текстового режима hard-stop не нужен: он дешёвый, поэтому ограничиваемся планом вопросов и ручным завершением.

### 6.4.1. Интеллектуальные подсказки во время ответа

Это важная дифференцирующая функция JobAI: сервис не только оценивает уже готовый ответ, но и помогает пользователю научиться отвечать **в моменте**, когда он теряется, уходит от вопроса или не знает, что сказать дальше. Для realtime voice подсказки входят в основной скоуп, а не откладываются на V2.

Принцип: подсказки — это **управляемый тренировочный режим**, а не постоянное вмешательство интервьюера. Пользователь управляет ими во время ответа:
- **Без подсказок** — экзаменационный режим, максимально близко к реальному интервью.
- **По запросу** — пользователь нажимает кнопку «Подсказка» или говорит «дай подсказку», а сервис показывает короткий ориентир.
- **Realtime-подсказки** — AI анализирует live-транскрипт и предлагает подсказку только при явных сигналах затруднения.

Где показываем:
- **Основное место — правая боковая панель «Подсказки»** рядом с лентой интервью. Это лучше tooltip: подсказка не исчезает случайно, не перекрывает текст ответа и её удобно читать во время речи.
- **План вопросов не является подсказкой.** В панели подсказок он может быть доступен только как сворачиваемый блок «План» или отдельная кнопка предпросмотра. По умолчанию пользователь видит именно помощь к текущему ответу, а не список будущих вопросов.
- **Внутри чата** можно показывать маленький маркер «появилась подсказка», но не вставлять подсказку как реплику интервьюера, чтобы не смешивать интервью и coaching layer.
- **Tooltip используем только для терминов, help-иконок и пояснений после ответа.** Если нужен tooltip, используем `floating-vue` и директиву `v-tooltip` как в Mentala. Глобальные стили адаптируем под нашу дизайн-систему: CSS-переменные, light/dark, glass background, `preventOverflow`, `shift`, без хардкода цветов.
- На мобильном подсказка открывается нижней панелью: компактный chip «Подсказка» над input/voice controls, tap раскрывает sheet.

Что показываем в подсказке:
- структуру ответа, например STAR/ситуация-действие-результат;
- какие факты стоит упомянуть именно по этой вакансии/роли;
- какие термины или определения важно знать;
- «о чём можно сказать дальше», если пользователь остановился;
- после ответа — пример сильного ответа, но отдельно от live-подсказки, чтобы пользователь не просто читал готовый текст.

Когда показываем realtime-подсказку:
- пользователь прямо попросил подсказку голосом или кнопкой;
- пауза дольше заданного порога после начала ответа;
- пользователь сказал «не знаю», «затрудняюсь», «не уверен»;
- ответ повторяется, уходит от темы или не содержит конкретного примера;
- live-транскрипт показывает, что не хватает ключевого блока: ситуация, действие, результат, цифры, связь с вакансией.

Технический принцип: не гонять отдельную LLM на каждый звук/секунду. Для каждого `interview_plan_item` заранее генерируем `hint_pack`: структура ответа, опорные пункты, термины, запрещённые/слабые формулировки, пример сильного направления. В realtime voice `HintEngine` слушает live-транскрипт, применяет throttling и сначала выбирает подсказку из готового `hint_pack`; короткую генерацию делает только если готовой подсказки недостаточно. Все показанные подсказки сохраняются в metadata, чтобы в отчёте отметить: ответ был самостоятельным или с подсказками.

### 6.5. Экран отчёта
- **Шапка:** общий балл 0–100 + вердикт («Готов, но дожми конкретику»).
- **Карточки-метрики:** структура · конкретика · релевантность вакансии · уверенность речи · риск-фразы · «вода».
- **Радар/бар-чарт** по критериям (apexcharts).
- **План интервью:** какие вопросы были запланированы, какие заданы, какие пропущены из-за времени. Пользовательские вопросы помечаются бейджем «ваш вопрос», вопросы JobAI — «JobAI».
- **По каждому главному вопросу (аккордеон):** вопрос · источник вопроса · transcript ответа · уточнения · использованные подсказки · что хорошо · что слабо · **как сильнее** · образец по STAR · мини-тренировка на завтра.
- Если пользователь использовал подсказки, отчёт не «наказывает» механически, но честно помечает это: «ответ с подсказкой» / «самостоятельный ответ». Это важно для тренировочного прогресса.
- В тексте ответа и вопроса подсвечиваем ключевые термины, недостающие смысловые блоки и риск-фразы. Для пояснений используем `v-tooltip`/popover: что означает термин, почему он важен, как его лучше раскрыть.
- **Финал: «3 главные вещи исправить до интервью».**
- Действия: «Скачать PDF» · «Сохранить сильные ответы в библиотеку» · «Пройти ещё раз» · «Поделиться».

### 6.6. История
Список сессий: вакансия/роль, дата, балл, динамика. Фильтр по вакансии. Клик → отчёт.

### 6.7. База вопросов (SEO + тренировка)
- Каталог по сферам/ролям; страница вопроса: формулировка · сильный ответ (STAR) · типичные ошибки · «как звучит слабо».
- На каждой странице — CTA **«Потренировать этот вопрос вживую»** → в тренажёр.
- Публичные страницы (для SEO и неавторизованных) с мягким пейволлом на «потренировать».

### 6.8. Тарифы и оплата
- Страница тарифов (см. раздел 9), оплата через YooKassa, статус/баланс сессий в шапке.
- Пейволл-модалка появляется по триггеру (после бесплатной сессии / при доступе к платной фиче) — функции **видимы**, не скрыты, с иконкой тарифа (паттерн Mentala).

### 6.9. Профиль/настройки
Аккаунт (Telegram/email), язык, история оплат, удаление данных, согласия. Привязка Telegram (если зашёл с веба).

## 7. Telegram-бот — детальный UI/UX

### 7.1. Старт и онбординг
- `/start` → приветствие 1 экран: «15-минутная репетиция собеседования по твоей вакансии. Отвечаешь голосом — получаешь разбор.»
- Кнопки сценариев: «HR-собеседование» · «Профессиональное» · «Зарплатные переговоры» · «Английское».
- Просьба: «Вставь вакансию (ссылка hh.ru или текст) или выбери профессию». Опц.: «Прикрепи резюме (PDF/текст)».

### 7.2. Настройка (инлайн-кнопки)
Роль/сфера (или из вакансии) → уровень → цель сессии (быстрая/стандартная/глубокая) → свои вопросы (опц.) → источник вопросов (JobAI / мои+JobAI / только мои) → язык → режим интервьюера. Минимум шагов, всё кнопками.

### 7.3. Сессия
- Бот шлёт вопрос **текстом + голосовым** (TTS).
- Пользователь отвечает **голосовым сообщением** (нативно) → транскрибация.
- Без мгновенного фидбека; при поверхностном ответе — 1 уточняющий.
- Прогресс показывается как «Вопрос 3 · осталось примерно 7 минут», а не как жёсткое «3 из 6».

### 7.4. Краткий отчёт + мост на сайт
- После сессии — **краткий отчёт прямо в боте:** балл, топ-2 сильное, топ-2 на доработку, «3 вещи исправить».
- Кнопка **«Полный разбор на сайте →»** (magic-link, см. раздел 8).
- Пейволл: 1 бесплатная быстрая сессия, дальше — пакеты через Stars или «продолжить на сайте».

## 8. Связка Telegram ↔ Web (бесшовная авторизация)

Логика (без кода):
1. Пользователь в боте жмёт «Полный разбор на сайте».
2. Бот формирует **одноразовую ссылку с подписанным токеном**, привязанным к `telegram_id` и конкретной сессии.
3. Сайт по токену **молча создаёт/логинит аккаунт** (passwordless) и открывает **именно тот отчёт**.
4. Если пользователь раньше не был на сайте — аккаунт заводится автоматически, регистрация не требуется; email можно добавить позже в профиле.
5. Обратная привязка: если пользователь начал с веба, в профиле — «Привязать Telegram» (Telegram Login Widget).

Результат: один прогресс на двух платформах, ноль трения при переходе бот → сайт.

## 10. База вопросов — генерация и структура

- **Источник:** генерируем сами через LLM по нашей таксономии (сфера → роль → тип вопроса), затем ручная вычитка. Конкурентов не парсим (правовой риск + IT-перекос). Awesome-список используем лишь как ориентир тем.
- **Единица базы:** вопрос → сильный ответ (STAR) → типичные ошибки → «как звучит слабо» → теги (сфера, роль, тип: HR/поведенческий/профессиональный/стресс).
- **Роль:** верх воронки (SEO + бесплатная ценность + ретеншн), связана кнопкой с платным живым тренажёром.
- **Объём старта:** 300–1000 пар по приоритетным сферам (не только IT).

Realtime voice — дорогой режим, поэтому считаем его отдельно от обычных интервью:

- пользователь может докупить add-on пакет минут;
- текущая сессия не обрывается на soft-limit, но hard-stop защищает экономику продукта от разговоров на 1-2 часа;
- в billing нужно хранить начисления минут, списания по realtime session events и срок действия add-on пакетов.

## 13. Инфраструктура и деплой (решения)

### 13.1. GitHub
**Рекомендация: новый приватный репозиторий под существующим личным аккаунтом.**
Третий аккаунт/почту заводить не нужно — это лишняя операционная нагрузка (ещё один логин, 2FA, ключи) ради непроверенной гипотезы. Отдельный аккаунт под Mentala был оправдан (продукт/компания), но для соло-теста это преждевременно. Если JobAI «взлетит», репозиторий легко перенести в отдельную организацию/аккаунт **с сохранением истории** (GitHub Transfer). Итог: один новый private-репозиторий на личном аккаунте сейчас → миграция позже при необходимости.

### 13.2. Сервер и база данных
Размещать второе приложение на существующем сервере на другом домене — **стандартная практика** (виртуальный хостинг + реверс-прокси; у Mentala уже Caddy). Запускаем JobAI на другом порту, добавляем блок в Caddyfile на поддомен — и всё.
- **Postgres:** тот же инстанс, что у Mentala, но **ОТДЕЛЬНАЯ база `jobai`** (не общая схема/таблицы). Смешивать два продукта в одной БД нельзя — риск для живой Mentala. Стоимость нулевая, изоляция чистая.
- **Redis:** тот же инстанс, **отдельный logical DB / префикс ключей**.
- **Важно:** для теста подключаемся к dev-окружению, **не к продакшен-БД Mentala**. Тяжёлый AI-трафик (Realtime Voice, генерация отчётов) мониторим, чтобы не мешал Mentala.

### 13.3. Домен
Домен пока **не покупаем**. На время теста — **поддомен на домене Mentala** (например, `jobai.mentala.app`), указывающий на новый сервис. Быстро, бесплатно, без возни. Перед боевым запуском (когда гипотеза подтвердится) — выносим на отдельный сервер и покупаем собственный домен (важно для SEO базы вопросов).

> Доступ по `ssh mentala-yc-dev` я НЕ использую: лезть в живой сервер из песочницы рискованно и не нужно. Конфиг подключения к БД повторил по образцу Mentala (Drizzle + pg, строка из `NUXT_DATABASE_URL`).
