# ROADMAP — поэтапная реализация JobAI

*План разработки: что и в какой последовательности делаем. Дополняет `ТЗ-тренажёр-собеседований-v1.md` (продукт/UX). Июнь 2026.*

---

## Как мы работаем

- Двигаемся **вертикальными срезами**: сначала самый дешёвый сквозной путь (текстовое интервью end-to-end), потом наслаиваем голос, Zoom-UI и монетизацию. Так раньше всего получаем работающий продукт.
- **Web-first.** Сначала доводим веб-версию до идеала и точно фиксируем структуру — и только потом, в самом конце, делаем Telegram-бота (когда уже понятно, что и как должно выглядеть). Это экономит переделки.
- **Авторизацию откладываем** на отдельный слой (Фаза 4). На ранних фазах используем лёгкую анонимную сессию (cookie с подписанным id), чтобы сохранять интервью/отчёты без полноценного логина. Когда добавим auth — привяжем анонимные данные к аккаунту.
- Каждая фаза заканчивается **проверяемым результатом**.
- env-ключи подключаем **по мере фаз** (в `nuxt.config.ts` → `runtimeConfig`); полный справочник — в `.env.example`.
- Перенос из Mentala — только релевантное (web), без Capacitor/Firebase/Apple/HeyGen.

Порядок: **1 → 2 → 3** (текстовый сквозной MVP) → **4** (авторизация) → **5 → 6 → 6.5** (голос + Zoom-UI + realtime-подсказки, доводим веб до идеала) → **7** (база вопросов + монетизация) → **8** (Telegram-бот, последним) → **9** (полировка/деплой).

---

## Фаза 0 — Скелет ✅ (сделано)

Nuxt 4 + Vue + Pinia + Tailwind + i18n(ru), Clean-arch сервер, Drizzle+Postgres, health-endpoint, дашборд-лейаут. БД `jobai` создана, миграции применяются. env перенесён из Mentala.

## Фаза 1 — Серверный каркас (без авторизации) ← начинаем сейчас

**Цель:** прочный фундамент бэкенда, на котором строится всё остальное. Без полноценного логина — но с анонимной сессией для сохранения данных.

Задачи:
1. **Единый формат ошибок** (`E_VALIDATION`, `E_AUTH`, `E_FORBIDDEN`, `E_RATE`, `E_NOT_FOUND`, `E_CONFLICT`, `E_UPSTREAM`, `E_UNKNOWN`) + хелпер `createApiError` + обёртка-хендлер, которая ловит ошибки и отдаёт единый JSON.
2. **Валидация DTO** через Zod (`shared/dto`) — хелпер чтения/валидации тела и query.
3. **Middleware:** request-id, заголовки безопасности, rate-limit (значения из `RATE_LIMIT_*`).
4. **Анонимная сессия:** cookie с подписанным id (`NUXT_SESSION_SECRET`), middleware кладёт `session` в контекст. Эндпоинт `GET /api/session/me`.
5. **Логгер** (pino) + расширение `runtimeConfig` нужными ключами.

**env:** `NUXT_SESSION_SECRET`, `RATE_LIMIT_*`.
**Результат:** есть каркас ошибок/валидации/middleware; анонимная сессия живёт между запросами; `/api/session/me` отдаёт id.

## Фаза 2 — Ядро: движок интервью (текст)

**Цель:** сквозное прохождение интервью текстом.

Задачи:
1. **Источник вакансии:** парсинг ссылки hh.ru (офиц. API) + ввод текста + загрузка резюме (PDF/текст → извлечение текста).
2. **LLM-движок вопросов:** промпт под вакансию/резюме/роль/уровень/режим; логика уточняющего вопроса.
3. **Ход сессии:** `interview_sessions` + `interview_turns` (привязка к анонимной сессии); цикл «вопрос → ответ → (уточнение) → следующий».
4. Сервисы — в `server/application/`; хендлеры тонкие.

**env:** `NUXT_OPENAI_API_KEY`, `NUXT_HH_API_BASE_URL`.
**Результат:** можно пройти интервью end-to-end в тексте, ответы сохраняются.

---

## Фаза 3 — Разбор и отчёт

**Цель:** после сессии — полноценный разбор.

Задачи:
1. **LLM-разбор:** критерии (структура, конкретика, релевантность, уверенность, риск-фразы, «вода»), сильный ответ STAR, «3 вещи исправить». Сохранение в `interview_reports`.
2. **Очередь BullMQ** для генерации отчёта (Redis `/1`).
3. **Экран отчёта** (веб): метрики + графики (apexcharts) + аккордеон по вопросам.
4. **PDF-экспорт**.

**env:** `BULLMQ_ENABLE_WORKERS`, Redis.
**Результат:** прошёл интервью → получил отчёт. После Фаз 1–3 — **текстовый MVP** для первых пользователей.

## Фаза 4 — Авторизация (отдельный слой)

**Цель:** полноценные аккаунты; анонимные данные привязываются к пользователю.

Задачи:
1. **Passwordless-вход через Telegram** (Telegram Login Widget на сайте + проверка подписи) и/или email-код.
2. Сессии httpOnly cookie + **CSRF** (Double Submit).
3. **Magic-link** (задел под будущего бота): одноразовый подписанный токен по `telegram_id` → молчаливый логин.
4. **Миграция анонимной сессии → аккаунт** (переносим уже пройденные интервью).
5. Проверка ролей (`requireRole`).

**env:** `NUXT_TELEGRAM_BOT_TOKEN` (для входа через Telegram), `AUTH_EMAIL_CODE_SECRET`, `EMAIL_HASH_PEPPER`.
**Результат:** можно войти; история и прогресс закреплены за аккаунтом.

---

## Фаза 5 — Голосовой слой (перенос из Mentala)

**Цель:** оба голосовых режима, как в Mentala.

Задачи:
1. **Диктовка голосом в textarea**: `app/composables/speech/*` (движок `webspeech`), `useSpeechEngine`, `VoiceInput.vue`, стор `speech`. Whisper — заглушка.
2. **Realtime Voice**: `useRealtimeVoiceSession`, `app/services/realtime/*`, `server/api/realtime/*` (OpenAI Realtime API), `realtimeVoiceUi`, `useMicPermissionGate`. Без Capacitor-веток.
3. **Realtime transcript → chat**: перенести подход Mentala `RealtimeVoiceChatAdapter`, чтобы события OpenAI Realtime попадали в единую ленту интервью как user/assistant messages.
4. **TTS** (озвучка вопросов): `useTTS` + `server/api/tts`; голос — Yandex SpeechKit (`lera`) или OpenAI TTS.

**env:** `NUXT_OPENAI_API_KEY`, `NUXT_FEATURE_TTS_ENABLED`, `YANDEX_SPEECHKIT_*`.
**Результат:** можно надиктовать ответ; работает realtime-разговор голосом.

## Фаза 6 — Веб-UI: Zoom-режим и кабинет (доводим до идеала)

**Цель:** веб-версия выглядит и работает как в ТЗ — финальный вид.

Задачи:
1. Дашборд (прогресс, «продолжить», быстрые сценарии).
2. Мастер создания интервью: источник, роль, свои вопросы, источник вопросов (JobAI / мои+JobAI / только мои), цель сессии по времени, тон интервьюера, выбор аватара. Режим ответа и подсказки управляются уже в комнате интервью.
3. **Zoom-режим сессии:** карточка интервьюера (фото + анимация речи), своя камера (`getUserMedia`, локально), единая лента чата, боковая панель плана/подсказок, панель управления.
4. История сессий, профиль, тарифные плашки.
5. Полная адаптивность (медиа-запросы), полировка анимаций и состояний.

**Результат:** «эталонная» веб-версия — структура зафиксирована.

## Фаза 6.5 — Интеллектуальные подсказки во время ответа

**Цель:** добавить обязательный тренировочный слой, в котором пользователь получает подсказки во время text/dictation/realtime voice и при этом сохраняется корректный разбор по каждому вопросу.

Детальный дизайн: `.docs/PHASE-6.5-DESIGN.md`.

Задачи:
1. Заменить жёсткий `questionCount` в UX на `interview_plan`: цель по времени, обязательные/резервные вопросы, пользовательские вопросы, источник вопроса.
2. Добавить блок «Свои вопросы» в создание интервью: текст, список или голосовая диктовка → нормализация AI → план.
3. Поддержать режим источника вопросов: только JobAI / мои+JobAI / только мои.
4. Реализовать `hint_pack` для каждого главного вопроса: структура ответа, опорные пункты, термины, слабые формулировки.
5. Реализовать `HintEngine` для realtime voice: live-транскрипт, паузы, просьба о помощи, уход от темы, throttling.
6. UI: правая боковая панель подсказок на десктопе, нижний sheet на мобильном. Tooltip через `floating-vue`/`v-tooltip` использовать только для терминов и help-иконок.
7. Отчёт: показывать пользовательские вопросы, использованные подсказки и статус «самостоятельно / с подсказкой».

## Фаза 7 — База вопросов (SEO) + монетизация

**Цель:** источник органики + приём денег.

Задачи:
1. **База вопросов:** генерация своей базы LLM (сфера → роль → тип) + вычитка; страницы каталога (часть публичные, SEO), CTA «потренировать вживую».
2. **Тарифы и пейволл:** лимиты (1 бесплатная сессия), realtime voice минуты, add-on пакеты минут, триггеры, иконки тарифа.
3. **Оплата:** YooKassa (сайт), вебхуки, гранты доступа.

**env:** `NUXT_YOOKASSA_*`.
**Результат:** можно платить; есть SEO-страницы.

## Фаза 8 — Telegram-бот (в самом конце)

**Цель:** второй канал на уже зафиксированной структуре веба.

Задачи:
1. Бот (aiogram/grammY): онбординг, настройка инлайн-кнопками.
2. Голосовая сессия в боте (голосовые → транскрибация).
3. Краткий отчёт + кнопка «Полный разбор на сайте →» (magic-link из Фазы 4).
4. Оплата Stars (1 бесплатно).

**env:** `NUXT_TELEGRAM_BOT_TOKEN` (новый бот через @BotFather).
**Результат:** полноценная сессия в боте, бесшовный переход на сайт.

> Делаем последним намеренно: к этому моменту структура и логика веба уже выверены, бот не придётся переделывать.

---

## Фаза 9 — Полировка, аналитика, деплой

Задачи:
1. Метрики теста: доля дошедших до оплаты, возврат (2+ сессии), CAC по каналам.
2. Sentry, логирование (pino), rate-limit, аудит безопасности.
3. Деплой: поддомен `jobai.mentala.app` через Caddy (отдельная БД `jobai`), CI на GitHub Actions.
4. Перед боевым запуском — отдельный сервер + свой домен.

> Веб можно задеплоить для теста уже после Фаз 1–6, не дожидаясь бота.
