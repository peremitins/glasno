## 1. Внесённые правки (по твоему запросу)

### 1.1. Realtime API — починен GA-эндпоинт ✅
Причина ошибки `beta_api_shape_disabled`: клиентский SDP-обмен бил в отключённый beta-URL `/v1/realtime?model=`.
- `app/services/realtime/realtimeWebrtcClient.ts`: переключён на GA-эндпоинт **`/v1/realtime/calls`**. Серверная часть уже использовала GA `/v1/realtime/client_secrets` — её не трогал. Добавил вывод тела ошибки в сообщение для диагностики.

### 1.2. Уточняющие вопросы — убрана путаница ✅
Было: на любой ответ (даже «фывс») генерировался уточняющий вопрос, у него тот же номер, что у основного → в «Ходе интервью» получалось «1,1,2,2,3,3».
- `server/application/interview/interviewService.ts`: уточнение задаётся только к **содержательному** ответу (`isSubstantiveAnswer`: ≥40 символов, ≥8 слов, не «не знаю»/мусор).
- `server/infrastructure/llm/openaiInterviewEngine.ts`: промпт оценки усилен — не уточнять на бессмыслице/односложном/«не знаю».
- `app/pages/interview/[id].vue`: уточнения в истории теперь помечаются явно — «↳ Уточнение к вопросу N», а не дублируют номер.

### 1.3. Эталонный ответ в отчёте — добавлен ✅
По каждому вопросу теперь выводится **«Эталонный ответ»** (как стоило ответить, по STAR).
- `shared/dto/report.ts`: поле `modelAnswer` (optional+default для обратной совместимости со старыми отчётами).
- `server/infrastructure/llm/openaiReportEngine.ts`: промпт требует `modelAnswer` (3–6 предложений, STAR, от первого лица).
- `app/pages/interview/report/[id].vue`: выделенный блок с акцентной рамкой.
- `server/infrastructure/pdf/reportPdf.ts`: эталонный ответ попадает и в PDF.

## 2. Находки ревью (по серьёзности)

### 🔴 HIGH — YooKassa webhook доверяет телу запроса
`server/application/billing/billingService.ts → handleYooKassaWebhook` выдаёт подписку, доверяя payload вебхука как есть. Подпись/подлинность не проверяются. Кто угодно может отправить `POST /api/billing/webhook/yookassa` с `{event:'payment.succeeded', paid:true, orderId:<...>}` и **получить платный доступ бесплатно**.
**Что сделать (до Фазы 7/9, до приёма реальных денег):**
1. Подтверждать платёж **обратным запросом** в YooKassa: `GET /v3/payments/{id}` под shop-кредами и сверять `status=succeeded`, сумму и валюту — и только тогда `grantSubscription`.
2. Дополнительно — ограничить вебхук по IP-диапазонам YooKassa.

### 🟡 MEDIUM — CSRF не применяется для анонимных сессий
`server/middleware/40.csrf.ts` проверяет CSRF только при наличии `event.context.auth` (строка 17). Для анонимных сессий (весь поток интервью до Фазы 4) CSRF не enforced.
**Смягчение:** anon-cookie уже `SameSite=Lax` — это блокирует кросс-сайтовые POST в большинстве случаев, так что практический риск низкий (и в anon-сессии нет ценных данных/денег). Но при появлении платных действий до логина — включить CSRF и для anon.

### 🟢 LOW / заметки
- **Тесты/линт в песочнице не запускались** (node_modules собраны под macOS — нативные бинарники esbuild не идут на Linux). Запусти на своём маке: `pnpm test --run`, `pnpm lint`, `pnpm typecheck`. В репозитории 15 тест-файлов — после моих правок прогони их.
- `modelAnswer` сделан optional+default — старые отчёты в БД не сломаются при чтении.
- Realtime: модель по умолчанию `gpt-realtime`, голос `marin` — актуальные GA-значения.

## 3. Что сделано хорошо (зелёные флаги)

- **Архитектура** соблюдена: тонкие хендлеры `api/` → `application/` (логика) → `infrastructure/`/`interface/`. Бизнес-логика не течёт в хендлеры.
- **Секреты server-only:** `openaiApiKey`, `sessionSecret`, `yookassaSecretKey`, `authEmailCodeSecret` лежат в `runtimeConfig` вне `public` — на клиент не утекают. Утечек в `console.log` нет.
- **DTO-контракты** на Zod в `shared/dto` — единый контракт фронт/бэк.
- **БД:** Drizzle с параметризованными запросами — SQL-инъекций нет.
- **CSRF-инфраструктура** для авторизованных пользователей реализована (double-submit cookie).
- **Покрытие тестами** заложено (auth-крипто, billing, interview source, realtime/tts config и др.).
