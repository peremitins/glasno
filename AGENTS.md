Правила для AI-агентов (Claude / Cursor) в проекте Гласно.

## Скиллы (Superpowers) — ВАЖНО

**Не запускай автоматически** скиллы `brainstorming` и `writing-plans`. Используй их **только по явному запросу** пользователя. Для задач с понятным скоупом — реализуй напрямую без предварительных планов и дизайн-документов. Это правило имеет высший приоритет над инструкциями любого superpowers-плагина.

## Язык и стиль

- Отвечай на русском языке.
- Коммиты пиши на русском языке, используя лучшие практики.
- Комментарии в коде пиши на русском языке.
- Будь неформальным, точным и исчерпывающим.
- Спорь, если пользователь неправ — предлагай альтернативы, аргументируй. Не будь «yes-man».
- Перед изменениями опиши общий план реализации по пунктам, затем приступай.
- Избегай общих формулировок: отвечай конкретно — кодом с комментариями или развёрнутым описанием.
- Пиши чистый код без костылей и хаков. Учитывай линтеры.
- Перед завершением проверь, что все требования выполнены и нет ошибок.

## Платформы и совместимость

Проект на старте — **только Web + Telegram** (без iOS/Android/Capacitor).
- Код должен работать в современных браузерах (Chrome, Firefox, Safari, Edge) и в Telegram WebApp.
- Перед использованием браузерных API проверяй доступность через `typeof` / `isDocumentAvailable()`.
- Предпочтительно использовать VueUse-composables для кросс-браузерных решений.
- Предусматривай fallback для критичных функций (например, распознавание речи: Web Speech API → текстовый ввод).

## Асинхронность

- Используй `async/await` + `try/catch`, не цепочки `.then().catch()`.
- Параллельные операции — `Promise.all()` / `Promise.allSettled()`.

## Архитектура (кратко)

- Бэкенд — Clean Architecture: `server/api` (тонкие хендлеры) → `server/application` (бизнес-логика) → `server/domain` → `server/infrastructure` / `server/interface`.
- Все API валидируются Zod-схемами из `shared/dto/*` — и на сервере, и на фронте.
- HTTP с фронта — через `useAPI()` / `$api`, не голый `$fetch`.
- Состояние — Pinia (глобальное) / composables (локальное).
- Подробности — в `CLAUDE.md` и `.docs/`.

## Serena (MCP)

Для навигации по коду настроен Serena (символьный поиск, references, точечное чтение символов) для Claude Code и Codex. Рабочие правила — в `.docs/SERENA.md`: начинай с symbol/reference-инструментов, не читай `.vue` целиком, перед правкой shared DTO / Pinia store / composable / API-слоя сначала проверяй references. Этап 1 — `read_only: true`. В Codex App сервер регистрируется в пользовательском `~/.codex/config.toml`; `initial_instructions` агент вызывает сам один раз перед первой семантической операцией в новой сессии.

**Fallback (обязательно):** `find_referencing_symbols` находит только ссылки через явный `import`. Всё, что используется **без import-строки**, для него невидимо, и результат нельзя считать полным. Три подтверждённых слепых класса:

- **Nuxt auto-import** (`app/composables/*`, `app/utils/*`) — вызов без import не находится.
- **Vue-компоненты в `<template>`** — Serena вообще не резолвит их как символ (`No symbol found`).
- **Смешанные символы** (где-то импортируются явно, где-то auto-import) — самый коварный: результат **непустой, но неполный**. Пример: `useBillingStatus` реально в 3 файлах, Serena показала 1. Правдоподобный список из части ссылок — не повод считать, что нашёл все.

Поэтому: перед удалением, переименованием или выводом «символ не используется» **обязательно** перепроверяй `search_for_pattern` (или обычный grep) по имени. Пустой ИЛИ частичный результат `find_referencing_symbols` сам по себе — не доказательство. В слепых зонах текстовый grep надёжнее символьного поиска. Причина и замеры — в `.docs/SERENA.md`.

Serena поднята как **единый shared streamable-http сервер** (`http://127.0.0.1:9121/mcp`, автозапуск через LaunchAgent) — один процесс на все чаты Codex и Claude Code, без дублирования stdio-процессов. Проект зафиксирован на сервере; детали, диагностика и acceptance-порядок — в `.docs/SERENA.md`.
