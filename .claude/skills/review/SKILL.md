# Code Review

Проверь текущие изменения на соответствие архитектуре и стандартам проекта.

## Шаг 1: Собери изменения

Выполни параллельно:
- `git diff` — нестейдженные изменения
- `git diff --cached` — стейдженные изменения
- `git diff HEAD~1` — если нет незакоммиченных, проверь последний коммит

## Шаг 2: Проверь по чек-листу

1. **Clean Architecture**: бизнес-логика в `server/application/`, а не в хендлерах `server/api/`.
2. **Zod DTO**: новые/изменённые API используют схемы из `shared/dto/*`; валидация и на сервере, и на фронте.
3. **HTTP с фронта**: через `useAPI()` / `$api`, не голый `$fetch`.
4. **Асинхронность**: `async/await` + `try/catch`, без цепочек `.then().catch()`; параллельно — `Promise.all()`.
5. **i18n**: нет хардкода UI-строк, всё через `t('...')`.
6. **UI**: Tailwind + shadcn-vue; цвета через CSS-переменные/токены, без `dark:`-хаков; адаптивность.
7. **Состояние**: глобальное — Pinia, локальное — composables.
8. **Безопасность**: нет секретов в коде/коммите; входные данные валидируются; нет очевидных инъекций.
9. **Совместимость**: браузерные API проверяются через `typeof`/`isDocumentAvailable()`; есть fallback.

## Шаг 3: Вердикт

Кратко: что хорошо, что нарушено (со ссылками на файлы/строки), что исправить до коммита.
